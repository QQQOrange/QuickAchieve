# Quick Achieve v2.23.88

> 设置项的默认值从此只有**一个来源**（Rust 的 `Config::default()`），
> 每张设置卡片多了一颗「恢复本节默认」；顺手修掉了 i18n 手工改稿被
> 生成器覆盖的漂移。

## 一、默认值单一来源

- 新增后端命令 `defaults_view()`：把 `Config::default()` 渲染成和
  `get_config` 完全相同的 camelCase 视图；
- `config_view()` 拆出 `config_view_of(&Config)`，两个入口共用同一份实现；
- 设置页的「恢复本节默认」点的时候才去后端取默认值（懒加载），
  启动时序再乱也不会出现按钮装不上。

以前默认值散在三处：Rust `Config`、`SLIDERS` 常量、HTML 初值。
`barBgAlpha=0` 被 `|| 55` 吃掉、`trans_add_to_bar` 迁移都是这种漂移的
产物。现在至少"恢复默认"这条路只认 Rust。

## 二、每张卡片「恢复本节默认」

- 设置页 46 张卡片里有可恢复控件的，标题右侧多一颗小按钮；
- 只处理**数字滑块 / 布尔开关**：
  - 路径、凭据、数组（引擎列表 / 收藏 / 网格页）**一律不碰**；
  - 只提交当前值和默认值不同的字段，没改过的卡片不写盘；
- 滑块的"样式默认"单独处理：磨砂这一节恢复的是**磨砂开着**的默认强度
  **12**，而不是全局默认样式里的 0（0 会把磨砂关掉）；
- 点击后 `set_settings` 一次性批量提交，配置广播回来即时刷新 UI；
- 实测：把磨砂强度改成 21、底板透明度改成 0，点一下 →
  `barBlur` 回到 12、`barBgAlpha` 回到 55。

## 三、i18n 漂移修复

- `ui/i18n.en.js` 是**生成文件**，最近几次手工改的英文（移远收起文案、
  静态磨砂文案、底板透明度）被生成器覆盖了；这次把缺的 key 补进
  `_i18n_parts/42_fix_v2388.json` 并重新生成；
- 顺手补了「恢复本节默认」按钮、标题、toast 的英文；
- 英文覆盖检查的允许残留从 3 调到 5，并在 `tools/check-all.js` 里写明
  这 5 条是用户数据类固定项（横条/设置页里的引擎名「百度」+「简体中文」），
  不是漏翻。

## 四、发现并修掉的一个注册缺口

`defaults_view` 一开始只加了 `#[command]`，忘了加进 `main` 的
`generate_handler![...]`，前端报「未知命令」。命令表一致性检查只查
`invoke ↔ fn`，查不到"函数存在但没注册"——这条留给 E2E 固化后兜住。
