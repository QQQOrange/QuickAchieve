## 1. 审视方法

不是"读一遍找感觉"，每一条都落到可复现的证据上：

| 手段 | 做法 | 抓到了什么 |
|---|---|---|
| 命令层双向一致性 | 正则对齐 `generate_handler![…]` / `#[crate::t::command]` / 前端 `invoke('…')` 三边 | **0 处**不一致（216 注册 / 213 定义 / 190 被前端调用），说明这一层是干净的 |
| 静态一致性 | `audit/static-audit.js`：重复 id、`$('id')` 找不到元素、`t()` 未收录、事件名两端不对称 | 3 条 `$('id')` 告警均为动态生成（误报）；事件名两端都对得上 |
| 无头 UI 测试 | 跑仓库自带的 `tools/test-ui.js` | **10 条失败**，逐条查下来全是"测试没跟上产品改版"，其中 1 条掩盖了真 bug（见 §3.1） |
| 补测空白页 | 新写 `tools/test-pages.js`，覆盖 qr / qrgen / gridpreview / picker / toast / lock / update | 页面本身没问题，但**证明它们能加载、关键按钮能调对命令** |
| 英文覆盖度 | 新写 `tools/i18n-coverage.js`：真跑 i18n 运行时切 en，数页面残留汉字 | ocr.html 17 条、qr.html 1 条（见 §4） |
| 分模块深读 | 10 个审查单元并行（按文件/行段切分），要求"必须给出行号 + 原文 + 复现条件 + 置信度" | 30+ 条候选，逐条复核后采纳 24 条 |

> 复核原则：**不采信"看起来像 bug"**。每条都回到源码确认，能写单测的补单测（标点、有道签名、多行拼接各加了断言）。

### 2.3 顺带修掉的连带问题

- **OCR 多引擎串场**：上一轮迟到的结果会删掉新一轮已入账的条目、推一帧"旧图 + 旧文字 + 新分段"，并把状态条提前标成"完成"。现在按代次丢弃（`gen != OCR_PNG_GEN` 直接 continue，收尾也加闸）。
- **OCR 超时被当可重试**：25s 超时 × 3 次 ≈ 76 秒空转，且带图 POST 可能重复计费。超时不再重试。
- **翻译接口地址留空静默回落到硅基流动**：用户的 Key 会被 Bearer 发到没选过的第三方。现在直接报"还没填接口地址"。
- **恢复备份不同步本机真实状态**：`autoStart` 只写了配置、没写 Run 注册表；`autoElevate` 没写 `elevate.pref`。现在恢复后按配置落地一次。
- **托盘菜单回调在持锁期间执行**：`refresh_tray` 会反过来 `SLOT.lock()` —— 修好 #2 之后这里立刻会变成主线程死锁。回调改成 `Arc`，锁内只复制、锁外调用。
- **`parse_youdao_reads_lines_and_error_codes` 丢了 `#[test]`**：有人加新测试时把 `#[test]` 写重了，这条从未执行过。补回后立刻通过 —— 说明解析本身是对的，只是没人验证。

## 5. 结构改动（只做零行为变化的）

| 改动 | 说明 |
|---|---|
| `trayhost` 回调类型 `Box<dyn Fn>` → `Arc<dyn Fn>` | 为了让 `wndproc` 能在**锁外**调用回调（见 §2.3） |
| `settings.js` 新增 `gotoPane()` | `qs://goto-tab` 与 `qs://focus-tab` 两条通道原先各写一半，现在共用一处页名解析（顶栏页 / 分组子页 / 分组默认子页） |
| `settings.js` 的 `bound` 拆出 `ocrEngLoaded` / `transEngLoaded` | `bound` 同时表示"事件绑过了"和"首屏灌过了"，而广播可能先于首屏到达 → 引擎表整场为空 |
| `webdav::latest` 标 `#[allow(dead_code)]` + 注释 | 启动同步不再用它（见 #8），但它是诚实通用工具、单测在用；注释写明"别拿去决定云端哪份是配置" |

**刻意没做的**（评估过、收益不抵风险）：

- **`main.rs` 2.5 万行拆模块**：纯搬迁，但要动 `AppState`/`APP`/`STATE` 全局句柄的可见性，跨文件重导出容易引入"能编译但语义变了"的问题。这一轮以修 bug 为先，不适合同时做大规模搬迁。
- **「清理冗余数据」里的「孤立自定义图标」分组**：判定条件确实写成了重言式（`dir_icon_defaults()` 把 icons 目录**全部**图片都收进集合，`!dir_icons.contains()` 恒假），所以这一项永远为空、永远清不掉东西。**但正确修法需要知道"当前有哪些引擎名"**，而引擎目录在**前端**（`ui/data/engines.json` 内嵌在 exe 里，Rust 侧只认配置里的名字）。只按配置里的名字判，会把用户给"还没上横条的内置引擎"准备的 `<引擎名>.png` 当孤儿删掉 —— 这是删用户文件，宁可先不修。**当前行为是"安全但无效"**，比"修完开始误删"好。
- **`config` 迁移时图标/模型目录的搬运返回值被丢弃**（`let _ = move_dir(...)` 之后无条件删旧目录）：修法明确（失败就保留旧目录），但要构造"复制到一半失败"的测试环境才能证明修对了，本轮时间不够，留作下一轮。

# 轮 82（v2.23.3）：框选流程改版之后的复核

这轮改的是"框选之后到底做什么"：具体入口（OCR / 识图 / 二维码）**框完直接执行**，
另加一颗 **万能框选**（`@any`）负责"先框再挑"。交付之后又按用户要求把整条链路
重新审了一遍，下面按"**会坏功能 / 已经修掉 / 只影响观感**"归类。

## 9.1 会坏功能：哨兵准入白名单漏了 `@any`

`toggle_bar_engine_impl` 里准入是一串**手写**的 `&& engine != config::BAR_XXX`。
`@any` 加进 `is_bar_sentinel`（配置层）之后，`Config` 读回来不会被剪，
但设置页那颗「＋ 加进横条」走的是**另一条**判据 —— 不在那串里就静默拒收。

症状：点「＋ 加进横条」没反应、列表不变、横条上也不出现。
和历史上 `@qr` / `@qrmake` / 绑定模型格子绊的是同一个坑（代码注释里已经记过三次）。

修法：把这串判据补上 `BAR_ANY`。**两处判据是两个独立的坑**，所以各钉一条测试：

- `config::sanitize_tests::universal_capture_sentinel_is_bar_member`
  —— `is_bar_sentinel` 认它、`prune_undefined_bar_engines` 不剪它；
- `tests::toggle_bar_engine_accepts_custom_engines` 里追加 `@any` 的
  入列表 / 去重 / 移出三段。

## 9.4 复核后仍然成立的口径

- **默认值四处一致**：`Config::default()` 里 `region_adjust: false`、
  `#[serde(default)]`（bool → false）、`set_setting` 的 `unwrap_or(false)`、
  前端 `!!(c && c.regionAdjust)` —— 没有一处残留 `default_true` / `unwrap_or(true)`。
- **旧键名彻底退场**：全仓 grep `regionHold` / `region_hold`，只剩
  `config.rs` 的注释（解释为什么改名）和两份历史发布说明。
- `qsFuncBound` 的正则只认 `ocr|img|trans|txt|wrap`，`@any` 不会被误判成"绑定模型的格子"；
  `is_model_sentinel` 也没加它 —— 它本来就不绑模型。
- 恢复旧备份（v2.23.2 及更早）时，`apply_view` 里 `if let Some(x) = b("regionAdjust")`
  会因为键不存在而**跳过**，用户当前的 `regionAdjust` 不会被悄悄重置 —— 这是想要的行为。

## 9.5 已知的取舍（不是 bug）

- `复制图片` 仍然**只在**动作条上（也就是"万能框选"或显式打开"框选后可调整"时）。
  具体功能那三条路里没有它，因为"复制成图片"不属于它们各自的语义。
- `?mode=any` 时 `defaultAct()` 回落 `ocr`：用户没在这个模式下点过任何动作时，
