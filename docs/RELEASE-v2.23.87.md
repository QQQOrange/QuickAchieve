# Quick Achieve v2.23.87

> 「鼠标移远就收起」再修一刀：**指针没动过就不算“移远”**，不会再出现
> “横条刚弹出来、手指都没动、1 秒后自己没了”；真正移开时 0.35 秒收起。

## 日志里看到的问题

14:34:23 的真实日志（多行划词）：

```
show_bar ... caret=(1391,1166)-(1391,1231) 鼠标=(1391,1190)
layout: win=(1343,1195,298,162) inner=(48,48,202,66)
bar-away: 指针离横条 42px（阈值 40px）—— 开始计时
bar-away: 指针连续 631ms 离横条 696px —— 收起横条
```

横条挂在选区下方，指针停在选区中间，**离横条 53px > 阈值 40px**。
用户一根手指都没动，横条弹出 0.44s 后就开始倒计时，1 秒后自己消失。
这看起来就像“移远收起乱触发 / 没按预期工作”。

上一版（v2.23.86）把距离基准从窗口外框改成可见横条，解决了“移很远才收”；
但同时也让“弹出时指针本来就在 40px 外”变成了立即倒计时 —— 这次补上。

## 这次改了什么

- **先动才算**：横条弹出时记下指针位置，指针累计移动 ≥ 6px 才开始按距离判断；
  没动过就一直等（无操作自动收起仍然兜底）；
- 一旦动过：
  - 指针离**可见横条**超过阈值 → 0.35 秒后收起（原来 0.6 秒，实测偏慢）；
  - 中途回到阈值内 → 计时清零，重新开始；
- 新增一行诊断日志：`bar-away: 指针移动 ≥6px —— 开始判距离（阈值 40px）`，
  下次再有“为什么不收/为什么乱收”，直接看这一行；
- 设置页文案同步成「约 0.3 秒后收起」。

## 现在的手感

| 场景 | 行为 |
|---|---|
| 横条弹出，指针不动 | 保持显示（3–5 秒无操作才由 idle 收） |
| 指针移到横条上 | 保持 |
| 指针移开超过阈值 | 约 0.35 秒后收起 |
| 移开后又回来 | 重新计时，不收起 |
| 阈值设 0 | 关闭这条逻辑 |
