# Quick Achieve v2.23.16

> 修两处"复制到上一张图的文字 / 翻译对不上原文"的真 bug，外加恢复快照与看门狗的收尾。

## 一、结果窗「都看」多框：复制/翻译/打开链接取错文字

`curTa()` 在没有"活动框"时会退回隐藏的 `#text` —— 可多框模式下 `renderResultText`
**跳过** `setText`，所以 `#text` 里躺着的是**上一张图**的文字（冷启动时是空串）。

后果：

- 冷启动就点「复制」→ 提示"没有可复制的文字"，看着像按钮坏了；
- 先单框、后转多框 → 复制 / 翻译 / 「打开链接」拿到上一张图的内容，
  **甚至会把上一张图里的网址打开**。

现在：多框时优先取"第一个有内容的框"，都没有才取第一个框。

顺带：换「同时识别」名单时会重建这些框（`innerHTML=''`），屏幕上已经显示的结果会被清空 ——
现在按 engine id 先存一份、重建后回填。

## 二、翻译窗：新文字被静默丢弃 / 清空后旧译文又冒出来

| 场景 | 以前 | 现在 |
|---|---|---|
| 正在翻长文时又送一段新文字进来 | 原文框和标题当场换了，但这一轮译文还在流式写进来 → **原文和译文对应的两段不同文字**，新文字要手点一次才翻 | 记一笔，本轮结束自动按新原文重跑 |
| 翻到一半点「清空」 | 1~3 秒后旧译文**又冒回空框里** | 清空作废当前轮次，迟到的结果不再填 |

另外修了「复制译文」取错框：原来恒取第一家 —— 同时翻两家、第一家失败（框空）、
第二家出了译文时，点复制拿到的是空串 +"还没有译文"，而旁边那格明明满屏文字。

## 三、恢复前的本机快照"写完就被删"

`stash_before_restore` 裁剪快照时按**整个文件名**排序，而家族里有两类名字
（`config.before-restore(…)` / `config.before-webdav(…)`），`r` < `w` ——
刚写的 restore 快照永远排第一，紧接着的 `remove(0)` 立刻把它删掉，
日志却写着"恢复前已留本机副本"。等 webdav 快照攒满额度，**挑错备份就没有退路了**。

现在按文件修改时间排序，只淘汰最旧的。

## 四、自动更新的看门狗让路

看门狗每 20 秒检查磁盘版本，而内建更新器也走"改名 → 换新 → 重启"这条路 ——
两边撞上会各起一个进程抢单实例（后一个立刻退出，但可能看到一次多余启动）。
现在看门狗发现更新正在进行就跳过。

## 安装

1. 下载 `QuickAchieve.exe`；
2. 覆盖你现有的那份（**数据目录 `Quick Achieve data\` 不受影响**）；
3. 双击运行。首次运行没有窗口是正常的 —— 在任务栏右下角托盘区找它。

> 从 v2.23.10 起，换上新 exe 后程序会**自己接管**（每 20 秒看一眼磁盘上的版本号，空闲时自动重启）。
