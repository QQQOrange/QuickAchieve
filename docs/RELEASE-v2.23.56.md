# Quick Achieve v2.23.56

> 修：**在微信里选中文字不弹横条**。

## 现场（来自你机器上的 log.txt）

```
start_capture: 拖选但没有选区（复制与屏幕识别都没拿到字）—— 这次不弹
confirm: 复制通道没拿到文字，且「没取到文字就不弹」开着 —— 不拿屏幕识别顶替，不弹
```

拖选**是**被检测到的。断的是取词：微信 4.x 是 Electron 自绘界面，划词时剪贴板里读不到文本、UIA 也拿不到。而 v2.23.8 为了防「拖滚动条也弹条」，规定「没取到文字就不弹」时**不允许屏幕识别兜底** —— 于是微信这条路彻底断了。

## 修法

新增开关 **「取不到文字时用屏幕识别兜底」**（设置 → 通用 → 触发，**默认开**）：

| 条件 | 行为 |
|---|---|
| 复制 / 无障碍拿到文字 | 照旧，直接用 |
| 都拿不到 + 选区宽高都 ≥ 8px | 把选区截图做一次屏幕识别，认出字就弹条 |
| 选区太细（拖滚动条 / 画布） | 不兜底，不弹 |
| 屏幕识别也认不出字 | 仍然不弹（这才是"真没选中"） |
| 程序在黑名单 | 一步都不会走到这里 |

## 为什么不是"无条件弹"

无条件 OCR 兜底会让**每一次拖动**都冒横条（v2.23.8 就是被这个问题逼出来的）。所以用「选区像个文本选区（宽高 ≥ 8px）」当门槛：微信里选一行字宽高都远超 8px，拖滚动条则是细长条。
