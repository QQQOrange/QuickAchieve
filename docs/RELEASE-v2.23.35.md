# Quick Achieve v2.23.35

> 主动优化：日志把有用信息淹了（65% 是鼠标流水），而且轮转会把"出事前那几分钟"抹掉。

## 一、日志里 65% 是逐次鼠标/键盘流水

拿你机器上的真实 `log.txt` 统计（7579 行）：

| 类别 | 行数 | 性质 |
|---|---|---|
| `hook: mouse DOWN/UP` | 2259 | 每次点击 2 行（系统级输入流） |
| `mouseup:` | 1130 | 每次点击 1 行 |
| `up-check:` | 1121 | 每次点击 1 行（还顺手取窗口类名） |
| `kbd:` | 448 | **每一次带 Ctrl/Alt 的按键**都写（Ctrl+C/V/Z/A…） |

合计 **4958 行 = 65%**。真正有价值的结论行（`start_capture:` / `show_bar:` / `capture:`）反而被淹没。

现在这些全部走新的 `win::trace()`：**默认不落盘**，设 `QS_TRACE=1` 后带 `[trace]` 前缀进同一份日志，排查时照常能看。

两个细节：

- **门槛放在调用点**（`if win::trace_on() { win::trace(&format!(..)) }`）——
  `trace` 内部会立刻返回，但 `format!` 在传参前就求值了，不这么写等于白省；
- 钩子回调在**系统输入关键路径**上（返回慢会被系统静默摘钩），
  每次点击少拼 4 个 `format!` + 少一次 `GetClassName`。

**实测：每次点击的日志从 ~4 行降到 0.45 行（20 次点击只新增 9 行）。**

## 二、日志轮转不再抹掉关键历史

原来超过 2MB 是**截断重写**：卡死/崩溃后重启，日志刚好越过 2MB，出事前那几分钟就被清空，只剩重启后的几百行——正好抹掉最需要的一段。

现在改名成 `log.1.txt`（覆盖上一代），主文件从空开始，总量上限 4MB，永远保留一节前一世代。

## 三、顺手量了长期运行的几个指标（都没问题，记录在此）

| 指标 | 实测 |
|---|---|
| 空闲 CPU（横条隐藏，20 秒） | **16 ms / 20 s ≈ 0.08% 单核** |
| 内存 | 工作集 43.7 MB / 私有 12.0 MB |
| 句柄 | 432（与 200 次显示/隐藏压测后的平台值一致，无增长） |
| 启动到托盘就绪 | ≈ 316 ms |
| 玻璃渲染循环 | 静止时自动停帧（不是常驻 rAF） |
