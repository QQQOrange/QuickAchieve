# Quick Achieve v2.23.123

> 自动取色才做明暗判定；固定亮色 / 暗色 / 跟随系统直接跳过。
> 判定从固定 5 帧改成「先 3 帧、判不出来再补 2 帧」，常见静态界面 **255 ms → 77 ms**。

## 一、没开自动取色就不抓屏

`current_theme()` 现在只认 `autotheme::needs_detection(theme)`：

- `theme == "page"`（设置里的「跟随页面」，也就是自动取色）→ 才调
  `autotheme::detect_cached()`；
- `light` / `dark` / `system` → 直接按设置或系统偏好算，不抓屏、不等帧。

真机验证：把主题改成亮色后触发横条，日志是
`show_bar: 耗时 锚点=0ms 让位=0ms 主题=0ms`，后面没有任何 `autotheme:` 行；
第一次（自动取色）同一位置仍有 `autotheme: 光标附近判定为 …`。

顺手把显式亮/暗的系统查询也省了：以前 `theme_dark_from(theme, win::apps_use_light_theme())`
无论主题是什么都会先查注册表，现在 `light` / `dark` 直接返回，只有
「跟随系统」或自动取色兜底才查。

## 二、判定时间：3 帧快判，判不出来再补

原来的做法是固定 5 帧、帧间隔 55 ms（4 × 55 = 220 ms 等待），实测约 255 ms。

现在：

1. 先抓 **3 帧**，间隔 **30 ms**（约 60 ms 等待）；
2. `decide()` 能判出深浅就立即返回；
3. 判不出来（视频、动画、灰区）才补到 **5 帧**，间隔 55 ms，保留原来的稳定性。

| 场景 | 改前 | 改后 |
|---|---:|---:|
| 静态界面（常见） | ~255 ms | **77 ms** |
| 画面在动 / 灰区 | ~255 ms | ~207 ms |
| 同一窗口 3 秒内重复 | 0 ms（缓存） | 0 ms（缓存） |

3 秒缓存没有动；判不出来仍然回退系统偏好，不会硬猜。

## 三、验证

- `cargo test`：**495 passed / 2 ignored**。
- `cargo clippy --all-targets -- -D warnings`：干净（仅 vendored `ureq` 一条 warning）。
- 新增单测：`只有跟随页面才需要抓屏判定`、`三帧静态界面就够判`。
- E2E：4/4（away / frost / reset / search）。
- 真机：自动取色下 `主题=77ms`；固定亮色下 `主题=0ms` 且无 `autotheme:` 日志。

## 四、说明

- 3 帧快判只用于“能明确判出来”的静态画面；30 ms 间隔足以让 30/60fps 的视频换帧，
  真遇到视频会落到补帧路径，不会拿单帧颜色硬猜。
- 首次判定仍有约 77 ms；这是“必须看屏幕”的成本，缓存只负责 3 秒内的重复划词。
