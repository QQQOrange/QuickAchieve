## 二、审计挖出来的（用户没提，但都会咬人）

### 运行时 / 兼容层
- `run_on_main_thread` 只投递不内联 → **7 个选文件/选目录命令把主线程堵死 2~5 分钟**，收藏夹"添加图片"永久冻死（v2.23.10）
- `async` 命令在主线程 `block_on` + 自唤醒忙等 → 翻译/重新识别期间**界面冻结 25~90 秒**、一个核满载（v2.23.13 / 14）
- 全屏遮罩的 Win32 强杀兜底是死代码（用 label 表判存在，而 label 早被同步摘掉）→ 主线程卡住时遮罩仍在吃鼠标（v2.23.10）
- `close()` 等于 `destroy()`：编程式关窗**不发** `CloseRequested/Destroyed` → 会话串台（v2.23.11）
- 托盘退出在菜单回调（主线程）里干等 6 秒；托盘图标退出后残留（v2.23.11 / 12）
- 主线程 panic 不落盘 → "程序突然没了、日志一片空白"（v2.23.10）

### 取词 / 横条 / 网格
- 穿透浮层占着鼠标落点 → 判"前台已换人"、**连 Ctrl+C 都不发** → 浏览器里选不中文字（v2.23.10）
- 浮层盖在终端上时会把 Ctrl+C 打进终端 = **杀掉正在跑的编译**（v2.23.10）
- 「都看」多框模式下复制/翻译/打开链接取的是**隐藏的上一轮文本**，甚至打开上一张图的网址（v2.23.16）
- 收藏面板不动渲染指纹 → 回「更多引擎」时**引擎列表消失且不可自愈**（v2.23.22）
- 拖动排序用 `CONF.barList`、渲染用 `barList()` → **按应用专项横条永远排不了序**（v2.23.22）
- 拖出横条移出后**红框永久挂着**；网格隐形抓手留在文字横条上，**拖一下就把格子尺寸写进配置**（v2.23.22）
- 包裹符号菜单不在 idle 白名单 → 挑 5 秒横条连菜单一起被收走（v2.23.22）
- 网格增删无串行化（快速连点吞操作）、长按拖动无异常收尾、默认引擎可能是功能哨兵（v2.23.23）

### 结果窗 / 翻译窗
- 失败原因写进**隐藏**文本框（多框时看不见，还会被当结果复制出去）（v2.23.19）
- 「文本处理」用 await 前的选区偏移写回 → **改坏新结果**；文本整理失败回滚把新结果盖回旧文本（v2.23.19）
- 翻译窗 `busy` 时新文本被静默丢弃；清空后旧译文回魂；「复制译文」恒取第一家（v2.23.16）
- `setScanning()` **生产路径从未调用** → "识别中禁止再点"整套保护是死代码，会并发跑两次 OCR（v2.23.21）

### 数据安全
- 「恢复全部默认」**连备份钥匙一起删** → 所有加密备份永久打不开；顺带真删用户图标、不留快照（v2.23.18）
- 保存失败只写日志 → 界面显示已生效、重启回滚（v2.23.18 / 19）
- 配置解不开就**永久锁写**，连"已从备份救回"也不写回 → 每次启动都丢设置（v2.23.17）
- 云端恢复判据依赖本机时钟 → 时钟慢就**每次启动被同一份旧云覆盖**；时钟回拨让自动备份永久停摆（v2.23.18）
- 轮转把"读不出的备份"当 0 分 → 换过密码后**8 份旧备份被删光**（v2.23.17）
- 清理逻辑删掉 `config.json.bak`（它正是主文件损坏时的最后兜底）（v2.23.17）
- 备份/导出/快照 5 处裸 `fs::write` → 断电留下半截文件，进清单、挤掉好的（v2.23.18）
- `--restore-probe` 号称只读，实际**写真实备份目录并删掉最旧一份**（v2.23.25）

### 体验 / 首次使用
- 全新安装**双击后什么都不发生**（这软件没有主窗口）→ 现在弹托盘气泡 + 打开设置（v2.23.26）
- 每次保存都在**解密全部备份**算完整度（27 份 = 27 次解密）（v2.23.26）
- 配置广播只发 3 个窗口 → 翻译窗/二维码窗/图标编辑器**永远收不到**，语言与引擎名单滞后（v2.23.28）
- ONNX 运行库缺失时每次启动刷两条**假 PANIC**（v2.23.28）
- 自动更新装好却不生效（管理员权限下杀不掉）→ 新增**磁盘版本自检 + 空闲自动接管**（v2.23.10）

## 四、明确判定「不改」的

| 项目 | 为什么不改 |
|---|---|
| 网格页不启动无操作计时 | 设计如此：网格是"停留态"面板，靠 Esc / 点别处 / 鼠标移远收起 |
| `favCollapsed` 不清理已删目录 id | 只是内存里几个字符串，重启即清，无行为影响 |
| `contextmenu` 重复绑定 `preventDefault` | 两次都只是阻止默认菜单，幂等且开销可忽略 |
| 便携版不主动提权 | 便携构建的既定策略（v2.23.24 把"显示"改成真实生效值，不再骗人） |
| 便携版会去 exe 同级 `Quick Achieve back` 找备份 | 这是升级不丢配置的机制；只有开发目录里塞了旧测试备份时才像噪音 |

## 五、留给后续的两条

1. **`save()` 只回 `bool`，不是 `Result`**：现在至少能弹提示，但调用侧拿不到"为什么失败"（磁盘满 / 只读 / 加密失败）。要彻底解决得改成 `Result<(), SaveError>` 并逐个调用点处理。
2. **云同步与本地恢复仍有毫秒级窗口**：v2.23.20 让恢复/导入与云操作共享 `SyncGuard`，但"取快照"是在锁外做的，理论上仍有极窄的重叠窗口。
