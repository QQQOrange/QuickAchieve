# Quick Achieve v2.23.6

> 快捷键撞车时，**只激发本软件**。别的程序（包括用 `RegisterHotKey` 占了同一组合的
> 工具）收不到这次按键。

## 问题

用户原话：

> 在这个软件里面设置快捷键，但这个快捷键跟系统的其他快捷键冲突的情况下。
> 那要保证这个快捷键只会激发我们这个软件里的功能。

根因不在"有没有判冲突"，而在**判得太晚**：我们的热键判断一直发生在消费线程里
（`Ev::KeyDown` 那条异步分支）。等它跑起来，按键早就传给目标程序了 —— 想拦也来不及，
所以以前只能"两家一起响应"。

## 现在的做法

在低级键盘钩子回调里**同步**判一次：命中就 `return LRESULT(1)` 把这次按键截住。
钩子回调是在按键进入目标线程消息队列**之前**执行的，所以：

- 本软件照常响应（截住的同时仍然投递给自己的消费线程）；
- 系统的、别的软件的同一个组合**什么都收不到**。

三条硬规矩（都有注释和单测）：

| 规矩 | 为什么 |
|---|---|
| 我们自己注入的按键**绝不吞** | 取词时模拟的 Ctrl+C、唤起外部软件的热键都靠它，吞了就自废武功 |
| **Ctrl+C 绝不吞** | 它是"借一下剪贴板"的复制键；不放它过去，目标程序压根复制不成 |
| 修饰键**全等**匹配 | 录的是 `ctrl+shift+g`，那 `ctrl+g` / `ctrl+alt+shift+g` 都不算 —— 否则用户会莫名其妙丢掉一片看起来无关的快捷键 |

## 新设置

**通用 → 触发 → 快捷键独占**（默认**开**）：

- 开着：只激发本软件；
- 关掉：两家一起响应（老行为）。

当前独占的是**收藏夹热键**与**网格页快捷键**（网格总开关关着时不占，免得白占一个组合）。

> ⚠ 拦不住的：`Ctrl+Alt+Del`、`Win+L`、`Win+Tab` 这类**系统保留键**在更上层就被
> 处理了，任何用户态钩子都拿不到 —— 录了也不会独占。设置页与帮助里都写明了。

## 安装

1. 下载 `QuickAchieve.exe`；
2. 覆盖你现有的那份（**数据目录 `Quick Achieve data\` 不受影响**）；
3. 双击运行。首次运行没有窗口是正常的 —— 在任务栏右下角托盘区找它。

> ⚠ 如果软件正在运行，Windows 会拒绝覆盖。先退出（托盘右键 → 退出），再替换。
