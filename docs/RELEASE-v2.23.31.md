# Quick Achieve v2.23.31（紧急修复）

> 确认了你说的现象：**有时候 Ctrl+C 会被我们覆盖掉**。已修。

## 问题：会把你刚按的 Ctrl+C 抹掉

取词（拖选时模拟复制）结束的那一刻，代码调用 `snap.note_our_write()`，
它的语义是"**把此刻的剪贴板序号当成我们写的**"。

而你完全可能正好在这一瞬间自己按了 Ctrl+C —— 横条弹出来、你以为没复制上，
或者你本来就想复制。此刻的序号是**你的**写入，基准被骗过去之后，
紧接着的"还原"就把我们备份的**旧内容**写回剪贴板：

- 你刚复制的文字没了；
- 粘贴出来是上一份旧内容 —— 表现就是"这次 Ctrl+C 没生效"。

因为要"恰好撞在时间窗里"，所以是偶发的（你说的"有时候"）。

## 修法：还原前比内容，不再只信序号

新增 `clip::restore_if_still_holds()`：只有**剪贴板里仍然是我们取走的那段文字**
时才还原。一旦出现别的新内容（你复制的、别的程序的），一律放手。

原则写进代码注释了：**宁可留一段选区在剪贴板上，也绝不能动用户刚复制的东西。**

两条合成复制路径都改了：

| 路径 | 场景 |
|---|---|
| `capture_selection` | 拖选取词（主路径） |
| `capture_exact` | 划词落到 OCR 时的那次精确复核 |

## 回归测试

新增 `clip::tests::用户自己复制的新内容不许被还原覆盖`：

1. 剪贴板=`OLD`，快照，写入 `OURS`（模拟我们的复制）→ 还原应当回到 `OLD`；
2. 再快照，写入 `THEIRS`（模拟你自己复制）→ **一步都不能动**，必须还是 `THEIRS`。

实测通过。

## 另外确认过的（都没问题）

- **键盘钩子绝不吞 Ctrl+C**：`should_swallow_down` 里有一条专门的提前返回
  （`vkCode == 0x43 && Ctrl && !Alt && !Shift && !Win → false`），
  代码注释也写着"吞掉等于把用户的复制功能弄坏"；
- **热键独占不包含 Ctrl+C**：只独占「网格页」和「收藏夹」两个快捷键，默认都不是 Ctrl+C。

4. 双击运行。
