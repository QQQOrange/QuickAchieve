# Quick Achieve v2.23.18

> 数据安全第二轮：五个"会悄悄毁掉用户东西"的地方。

## 一、「恢复全部默认」会连备份钥匙和图标一起删

那个按钮以前做三件**不可逆**的事，而且没有二次确认：

1. `*cfg = Config::default()` → 备份密码变空串 → 保存时会把 `backup.key` **删掉**。
   那是解开所有加密备份的唯一凭据 —— 删了之后，你手里有备份文件也**永久打不开**。
2. `drop_icon()` 把用户自己的图标文件**真删了**，而滚动备份只存文件名、不存字节
   → 图标永久丢失。
3. 不留任何快照，点错了没有退路。

现在：**重置设置，但不销毁凭据和素材** ——
先留一份 `before-restore` 快照、保留备份密码、图标文件不删（只是配置里不再引用）。

## 二、保存失败只写日志，用户永远不知道

改了设置，界面立刻生效（改的是内存），磁盘上什么都没变 —— 重启就回滚。
磁盘满、目录只读、网盘占用、杀软拦写入都会走到这条路，而以前只写一行日志。

现在第一次失败就弹一个**托盘气泡**，说明"这次改动重启后会回滚"
（只弹一次，不会每改一个设置弹一次）。

## 三、时钟慢一点就变成"每次启动都被同一份旧云端配置覆盖"

判"云端较新"是拿服务器 `Last-Modified` 和本机 `config.json` 的 mtime 直接比。
本机时钟慢几秒 → 每次启动都判云端较新 → 把同一份旧配置反复灌回来：
这次会话改的所有设置全白改，而且永远走不到"本机较新 → 上传"那一支。

现在恢复成功会写一个标记（文件名 + 服务器时间戳），**同一份只恢复一次**。

## 四、时钟往回拨会让自动备份永久停止

`last-backup.txt` 记的是上次成功上传的时刻。时钟回拨后标记停在"未来"，
`lt > last + 2` 永远不成立 → 判"配置没改动" → 启动/退出的自动备份**静默永久停止**，
日志还写着"没有改动"。现在标记超前当前时间 1 分钟以上就当它无效。

## 五、五处"半截文件"

备份、导出、快照原来是裸 `fs::write` —— 写一半断电就留下一个名字合法、内容半截的文件：
它会进备份清单、参与保留策略、把好的挤掉，等真去恢复才报错。备份恰恰是"主配置没了时
唯一的退路"，最不该是这样。

现在统一走 `write_atomic`（临时文件 + rename）。

## 安装

1. 下载 `QuickAchieve.exe`；
2. 覆盖你现有的那份（**数据目录 `Quick Achieve data\` 不受影响**）；
3. 双击运行。首次运行没有窗口是正常的 —— 在任务栏右下角托盘区找它。

> 从 v2.23.10 起，换上新 exe 后程序会**自己接管**（每 20 秒看一眼磁盘上的版本号，空闲时自动重启）。
