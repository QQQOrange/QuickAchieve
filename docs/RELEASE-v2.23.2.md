# Quick Achieve v2.23.2

> 这一版只改一件事：**你一开始选的是文本识别，框完就该直接识别**，不该再问你一遍。

## 问题

用户原话：

> 我选择了文本识别，画完框之后，它不会默认进行文本识别，还会弹出一个横条来问你是要翻译、
> 图片识别还是什么什么的。我都一开始选了文本识别，为什么后续还要再选一个？

这是 v2.16.0 引入的。当时把两件事捆成了一个开关：

```
「框选后先停一下」= ① 留出微调窗口  +  ② 必须再确认一次
```

① 是有价值的（框歪 5 像素能拖角改、能临时换用途），② 是多余的 —— 你在**开始框选之前**
就已经选好用途了。

## 现在的行为

| 时刻 | 发生什么 |
|---|---|
| 松开鼠标 | 选区留着、四角出手柄、动作条浮出，**但不再等你点** |
| 0.6 秒内不动鼠标 | **自动按你一开始选的那个用途执行** |
| 0.6 秒内动一下鼠标（>6px） | 取消自动执行，转手动：拖角微调 / 点按钮换用途 / 双击或回车执行 |
| 按 Esc | 照旧取消（并撤掉那个定时器） |

动作条上的文案跟着状态走：

- 自动阶段：「0.6 秒后自动**识别** · 动一下鼠标就停 · Esc 取消」，高亮的也是**识别**；
- 你一动手，切回手动文案：「拖角调整 · 双击**翻译** · Esc 取消」。

### 一个容易踩错的细节

自动执行用的是**这次框选的用途**（`?mode=`），**不是**"上次点过的动作"。

否则会出现更糟的情况：上次点过「翻译」，这次明明点了识别，0.6 秒后跑起来的是翻译 ——
那比多问一句更难理解。"记住上次用过的动作"这个能力只留给**双击 / 回车**这种你亲手做的动作，
动作条上会写明双击会执行哪一个。

## 其它

  关掉它仍然是"松手立刻执行"。
- `README`、`docs/HELP.md` 里描述这段交互的文字同步更新。
- 英文界面补了 2 条词条（新文案）。
- `tools/test-ui.js` 补 6 条断言：自动执行、动鼠标取消、记忆不越权。

## 安装

1. 下载 `QuickAchieve.exe`；
2. 覆盖你现有的那份（**数据目录 `Quick Achieve data\` 不受影响**）；
3. 双击运行。首次运行没有窗口是正常的 —— 在任务栏右下角托盘区找它。

> ⚠ 如果软件正在运行，Windows 会拒绝覆盖。先退出（托盘右键 → 退出），再替换。
