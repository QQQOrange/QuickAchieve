# Quick Achieve v2.23.17

> 数据安全审计挖出来的三条 —— 都是"平时不咬人、咬人就丢配置"的。

## 一、配置解不开就永久锁写，连从好备份自愈的路都被挡住

`LOCKED` 一旦置位**从不清除**。于是 `config.json` 只要解不开一次（截断 / 改坏一个字节 /
杀软插手 / 换了 Windows 账户），整个进程的保存就全部变成空操作 —— 只写日志，不落盘：

- 设置页改了立刻生效、**重启全没了**；
- 每次启动都复现，只能手工删 `config.json` 才能恢复；
- 更气人的是：`load_from` 明明已经从滚动备份救回了一份**好配置**，却既不写回也不解锁 ——
  那套"按完整度挑备份"的精细逻辑等于白写。

现在：**备份可用 = 数据没丢 → 解除锁**，并把这份好配置**强制写回主文件**
（坏文件已由 `preserve_broken` 留档，不会丢）。

## 二、读不出来的旧备份会被轮转删光

轮转时把"读不出内容"当成完整度 0。于是换过备份密码之后，旧备份全变 0 分，
"比本次更有价值的备份一律不删"这条保护直接失效（`0 > 新分数` 恒假）——
几轮保存就把 8 份旧备份全删光，而它们也许正是你还能用旧密码打开的唯一存档。

现在：解不开 = 不知道它多重要 → **一律保留**，只按时间淘汰确认可读的那些。

## 三、清理逻辑会删掉"恢复候选"

`config.json.bak` 和老式 `config.before-webdav-*.json` 被当成"旧命名垃圾"删掉，
可 `load_backup_of` 恰恰把它们当"主文件坏了之后的最后兜底候选"。
"主文件损坏 + 只剩这份老 bak" 的用户，唯一能救命的文件会被清理悄悄拿走。

现在它们都保留，交给保留策略 / 备份清单统一管。

## 安装

1. 下载 `QuickAchieve.exe`；
2. 覆盖你现有的那份（**数据目录 `Quick Achieve data\` 不受影响**）；
3. 双击运行。首次运行没有窗口是正常的 —— 在任务栏右下角托盘区找它。

> 从 v2.23.10 起，换上新 exe 后程序会**自己接管**（每 20 秒看一眼磁盘上的版本号，空闲时自动重启）。
